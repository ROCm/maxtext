# TensorFlow 2.20 cannot share a process with the ROCm JAX stack: importing it before JAX
# initializes the GPU backend aborts the interpreter, and importing it afterwards leaves RCCL
# unable to load the HIP runtime, so every collective fails with "unhandled cuda error". Both
# libraries link their own copy of XLA, and on 2.20 that collision became fatal on ROCm.
# 2.19 only warns ("computation placer already registered") and collectives keep working.
#
# These are overrides rather than constraints because the generated locks require tensorflow
# 2.20, and they are exact versions because the locks are installed with --resolution=lowest.
# The rest of the pins follow from tensorflow 2.19: it requires protobuf < 6 and tensorboard
# ~= 2.19.0, and tensorflow-text tracks the tensorflow minor.
#
# Each is the HIGHEST version tensorflow 2.19.1 admits, so they are already as close to the
# generated locks as this constraint allows. tensorflow-metadata stops at 1.17.3 because 1.21
# ships protos generated by protoc 6, and protobuf refuses gencode newer than the runtime
# ("Detected incompatible Protobuf Gencode/Runtime versions"), which takes tensorflow-datasets
# down with it. Re-check these ceilings whenever the tensorflow pin moves.
tensorflow==2.19.1
tensorflow-text==2.19.0
tensorboard==2.19.0
protobuf==5.29.6
tensorflow-metadata==1.17.3
